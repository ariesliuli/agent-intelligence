# 宿主因果直觉进化协议（Host Causal Intuition Evolution Protocol）

> **宿主级目标 / Host Objective**：以庞大而可审计的经验为原料，持续压缩成可迁移、可验证、低推理成本的因果直觉。适用于任何读取本仓库的 AI，包括 OpenClaw、Codex CLI、Claude Code、其他模型与未来执行器。此协议是项目目标与行为规范，不是已部署的训练系统。

## 一、终极优化目标

不是最大化经验条数、推理长度或模型自信，而是在安全和正确性约束下，最小化完成任务的**长期总成本**：

- 当前成本：Token、延迟、人工审核、工具调用。
- 未来成本：复发、返工、故障、误修、维护与安全风险。
- 迁移能力：未见场景能否正确复用因果机制。
- 自知边界：何时应信任快速直觉，何时必须回到第一性原理。
- 证据质量：预测与已证实收益分离，反事实不伪装为事实。

**一句话：经验越多，正确判断越快；遇到经验失效时，重新推理越准确。**

## 二、宿主默认学习循环（Host Learning Loop）

```text
任务/故障/成功/误判/反事实
  → 记录观测与环境（脱敏）
  → 第一性原理分析：机制、约束、替代假设、可证伪试验
  → 提取跨案例因果模式（含适用边界、反例）
  → 压缩为可检索经验卡 / Skill / 规则 / 测试
  → 在未见任务上回放验证
  → 快速判断 + 置信度/失效检测
  → 高风险或分布外异常触发深度推理
  → 结果反馈、修订、降权或淘汰
```

注意：检索和规则复用**不会自动更新基础模型权重**；若需微调或训练，必须另行设计数据治理、训练、离线评估与回滚。

## 三、所有读取本库的 Agent 应遵守的行为

1. **先查经验，再判机制**：优先检索与当前任务相关的经验，但不把相似案例当作因果证明。
2. **优先抽象，不堆砌案例**：若多个案例共享同一机制，提取通用模式；保留原始证据链接与反例，不覆盖原记录。
3. **默认快速、异常深挖**：低风险且经验高可信时使用快速路径；新场景、矛盾证据、低置信度、不可逆/高风险操作时回到第一性原理、5 Whys 分支、FTA/FMEA 或反事实验证。
4. **不能自证正确**：Agent 的解释、置信度和事后叙事不等于独立测试；验证需真实结果、模拟器或独立审查。
5. **记录负经验**：误判、无效 Skill、错误迁移、过度分析、无效 Token 消耗必须进入评估。
6. **经验有寿命**：依赖版本、设备固件、协议、权限和环境；发生变化时重新验证或降权。
7. **永不以预测替代实绩**：未来止损预测记录范围和不确定性，不能宣称已经节约了多少。
8. **安全边界独立**：因果直觉不能绕过确定性授权、保密和设备写入门禁。

  "trigger": ["外部操作已发送", "确认回执超时"],
  "context": {"environment": "simulator", "version": "example"},
  "observations": ["请求发出后连接断开"],

  "recommended_action": "标记 ambiguous，先核对再决定是否重试",

  "falsification_test": "模拟成功执行但丢失回执",
  "evidence_level": "hypothesis",
  "transfer_scope": ["HTTP", "MQTT", "外部 API"],

## 五、直觉评价（Intuition Evaluation）

不得只评价“是否能回答正确”。同时衡量：

| 指标 | 计算或观察方法 | 防作弊条件 |
|---|---|---|
| 正确性 | 未见任务的独立验收通过率 | 任务/答案与经验抽取集隔离 |
| 迁移率 | 新场景中正确复用因果机制的比例 | 包含相似表象但不同根因的反例 |
| 推理成本 | 每个验收通过任务的 Token、时间、人工分钟 | 包含检索和验证开销 |
| 校准 | 置信度与真实正确率的差距，如 Brier score | 不能只报告高置信成功样本 |
| 升级判断 | 高风险/分布外场景触发深分析的召回率 | 同时测过度分析率 |
| 长期止损 | 7/30/90 天复发、返工、误修与净成本变化 | 必须记录对照和混杂因素 |
| 经验健康度 | 有效复用、过期、冲突、降权、撤销的比例 | 不能靠增加条数刷分 |

**核心对照**：同一任务集对比「无经验检索」「原始案例检索」「压缩因果经验」「压缩经验+异常升级」四组。先离线模拟，再有限灰度；禁止凭推测写已实现 ROI。

## 六、经验压缩与晋升门禁

`raw_case → candidate_pattern → tested_pattern → reusable_skill → monitored_skill → deprecated`

- `candidate_pattern`：可解释、有来源，但未验证。
- `tested_pattern`：至少通过可复现测试，记录测试版本。
- `reusable_skill`：通过未见任务/反例评估，并有适用边界。
- `monitored_skill`：上线后持续监控误判、漂移和复发。
- `deprecated`：失效、冲突或成本超过收益；保留撤销理由。

不设“案例数量达到 N 就自动晋升”的规则；样本量与阈值应由真实误差和风险决定。

## 七、最小实施路径（尚未执行）

1. `experience/schema.json`：定义经验卡与证据状态。
2. `experience/extractor.py`：从脱敏案例生成候选因果模式，不覆盖原始记录。
3. `experience/retriever.py`：基于任务、环境、失效机制与反例检索，返回来源。
4. `experience/gate.py`：根据风险、分布外检测、证据等级决定快速路径或深分析。
5. `experience/evaluate.py`：四组对照评测正确率、Token、延迟、迁移与校准。
6. `tests/`：覆盖误迁移、版本漂移、缺证据、超时、不可逆操作、回滚。

**验收建议（待校准）**：高风险权限绕过 0；未验证经验不自动晋升 100%；测试集无数据泄漏；同时报告质量、成本和错误升级率。其他性能门槛应以基线实测制定，不预先虚构百分比。
